## Bugs found

1. **Phone position input was ~1/3 of the trainer's** (39f9667). `PolicyRunner.warm()`
   (and `benchmark()`) called `observe()` with made-up sensors lacking wheel
   distances; the position tracker took that as a counter jump, dropped the next real
   step's travel and leaked an extra step. Over the same minutes of e30112 the
   phone's travel peaked at 1158 phone mm, the trainer's at 1948. Every `pos_tau` run
   since e30107 had the policy acting on a position input three times smaller than
   the one it trained on. Fix: `observe(track=False)` for those calls.
2. The mouth on the face page changed length abruptly as it opened: canvas miter joins
   on its two sharp corners (1ffe951, `lineJoin = 'round'`).
3. The face page's sound toggle muted on the first tap (f65c3e8).
4. The app patch `dreamerbridge_cap_home_face.patch` was cut against app 103d11f7, so
   it no longer applies to ad447b6b; applied with a 3-way merge plus
   `check_app_copies.sh --fix` (now committed as 5ab754e7, so the patch is superseded).

## New env keys (all off by default)

| key | effect |
|---|---|
| `balance_bumper` | balance task pays minus this within `bumper_margin` of a bumper |
| `fatigue_s`, `fatigue_tol`, `fatigue_dead` | a wheel command held within tol fades linearly to 0 over fatigue_s (ineffective against the early sign-flipping; not used further) |
| `travel_lo`, `travel_hi` | needs `pos_tau`; commands pushing further the way the robot already went (leaky travel, phone mm) fade from lo to 0 at hi, latching at hi until travel is back under lo; braking/reversing always passes |

Fatigue and travel limits are applied on the phone (sent in pause frames,
`PolicyRunner.limit`) and in `robot.py:_advance` for sim/trainer-driven runs. Sign
check from e30112: wheel speed vs command corr -0.5, i.e. travel moves as -command.

`robot` block defaults changed: return home past 0.2 m at full wheel speed
(`home_radius 2436`, `home_speed 1.0`, `home_ramp 1200`). Alex then asked for 0.5 m,
and finally no return home at all (passed on the command line).

## App and tooling

- Face: springs on every feature, adaptive smoothing (0.5 s for small changes,
  0.05 s for big ones), red/green signed bars, a rotatable 3D valence-arousal-dominance
  box with wall shadows, dominance as posture (size, height, glow, lids, gaze),
  portrait layout, 30 fps at <= 1.5x resolution (it cost ~60% of a core at full res).
  Swipe left on the app's gauges to see it; `?robot=<phone>:8080` views it from a laptop.
- The app imports Python from `files/python` first and serves `files/face.html` if
  present: `tools/robot/dev/push_python.sh FILE.py` changes the phone's Python in
  seconds (app restart, the run keeps going). `--list` / `--clear`. **The phone
  currently has an override `policy_runner.py` (= dreamerv3 39f9667); clear it after
  the next app build.**
- arm64-only app build: 93 MB instead of 130, a Wi-Fi install 2:20 instead of 3:35.
- Gradle needs Android Studio's JDK (`JAVA_HOME=/Applications/Android
  Studio.app/Contents/jbr/Contents/Home`); the default JDK 26 fails.
