How to read this. Each row is one of the 8 blocks of the goal code; each column is a class for that block. Click a cell to set a block, or drag along a row to sweep it. Hover any cell to preview it without committing. The frame below each grid is what the world model decodes that goal into — code → goal_dec → deter → dyn prior → image decoder, the same path the agent renders its goals with.

Colours. Each grid is filled in its arm's colour, the same two as Figure 10 of the paper: grey for Director's independent categorical per block, blue for our discretized Gaussian. A selected cell outside the trained range keeps that colour and gains an orange ring.

Extrapolation. Columns outside 0–7 are class indices the model never saw, and the two arms reach them differently, because only one of them has a geometry to extend.

Ours works in the codebook. Inside the range the block walks the path through its 8 embeddings, so every integer still lands exactly on a trained entry. Outside, it leaves the end entry along the block's fitted line — the principal direction of all 8 entries — moving one average segment length per class: z(t) = e₀ + t·s·d below 0 and z(t) = e₇ + (t−7)·s·d above 7. Anchoring on the real end entries keeps the path unbroken at 0 and 7. Using the average step and the overall direction, rather than repeating whichever end segment happens to be there, matters: the two end gaps are the shortest in the block in all four environments, so repeating them made extrapolation crawl.

Director has no embedding, and its 8 one-hots are all the same distance apart, so there is no line to fit. It extends the one-hot family instead — i = clip(⌊t⌋, 0, 6), u = t − i, w[i] = 1−u, w[i+1] = u, giving [2, −1, …] at t = −1 — and those 64 numbers go straight into the decoder MLP as input activations. Defined, but with no learned metric behind it.

Distant jump. The paper's ε-greedy exploration move, on a button instead of firing with probability ε. From the current code c, a block at class cl can shift by at most max(c_l, C−1−c_l), so the furthest reachable code is d_max(c) = Σ_l max(c_l, C−1−c_l). A target distance is drawn with p(d) = 2d / (d_max(d_max+1)), which favours the big jumps and gives E[d] = ⅔(d_max + ½), then spread over the blocks within each one's capacity. d_max is a property of the code, not a constant — over uniform codes it averages 44, and only a code with every block already at 0 or 7 reaches 56 — so the rule draws d ≈ 30 in practice.

Try it on both sides. It is only worth doing because our index is ordered: on Director's code a large index gap does not imply a distant goal, so the same jump buys nothing there. That is the comparison the button is for.

What the agent thinks of the state. The five numbers under each frame are the agent's own heads, read at the same feat the image came from. manager · task (mgr_extr_val) is the discounted task return it expects from here. manager · explore (mgr_expl_val) is the exploration return, whose reward is the goal autoencoder's own reconstruction error — it scores how unfamiliar a state is, not how good it is, so a high value there and a low one next to it is the normal shape, not a contradiction. worker · on its goal (wkr_goal_val) is the only critic that needs a goal as well as a state; on its own it is read with the state as its own goal, the worker's best case. reward here and keeps going are the two heads the manager's critic is built out of. Same caveat as the frame: these were trained on features of real states, and a hand-edited code is only as real as the goal decoder makes it.

New state at a distance. Two distances, and they are not interchangeable. Class steps is the index distance the jump uses, Σ|Δc_l|, and is exact by counting — the same split rule as the jump with d handed in instead of drawn, so it starts from the current code rounded to whole classes. Goal space is the distance between the decoded goals, which no amount of counting gets you. It is reachable anyway because the class indices here are real-valued: the goal moves continuously along a ray in code space, so the page draws a random direction and walks out along it until the goal is the requested distance away. If the ray leaves the grid first, it says so and stops there. Watching how many class steps it takes to cover a fixed goal distance, on one arm against the other, is the same ordered-index question the jump asks from the other end.

Save and compare. save this state freezes the frame beside the live one and turns the panel into a two-state comparison: how far apart the codes are, how far apart the goals are and in what direction, how different the two pictures actually look, and every critic for both states with the change between them. The last two rows are the pair reading only the worker critic can give — what it makes of the saved state while aiming at the current goal, and the reverse. A large index gap with a small goal distance, or a big goal distance the pictures barely reflect, is the interesting case.

Both panels load the 3M-step milestone checkpoint of the better-scoring seed we ran for that environment. Rendering runs in float32 rather than the bfloat16 the runs trained in; the two differ by at most 4/255 per pixel (check_render.py).
